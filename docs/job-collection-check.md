# 공고 수집 검증 결과

확인일: 2026-10-12. 목적은 AI Agent 구현에 앞서 실제 공고 수집이 가능한지 확인하는 것이다.

## 현재 결과

| 출처 | 로컬 설정 | 실제 조회 결과 |
| --- | --- | --- |
| 사람인 | API 키·승인 정보 없음 | `not_configured`, 요청 0회 |
| 원티드 | client ID·secret·승인 정보 없음 | `not_configured`, 요청 0회 |
| 잡코리아 | 제휴 피드 URL·token·승인 정보 없음 | `not_configured`, 요청 0회 |

프로세스 환경변수와 루트 `.env`를 확인했다. 비밀값은 출력하지 않았다. GitHub Secrets의 설정 여부는 확인하지 않았다. **실제 API 수집 성공은 아직 검증하지 못했다.**

## 확인한 기능

- 수집기·조회 전용 명령의 자동 테스트 21개 통과. 외부 응답은 테스트 대체 객체를 사용했다.
- 기업군 확장, 정확한 기업 비교, 수정 시각 기준 조회, 기업별 페이지·요청 한도, 출처별 실패 격리를 확인했다.
- 새 명령 `collector/probe.py`로 조회만 할 수 있다. 키·승인 정보 누락 시 외부 요청을 하지 않는다.
- 조회 명령은 DB import·추천 계산·SMTP를 호출하지 않는다. 실제 검증에서도 DB나 이메일 상태를 변경하지 않았다.

## 실제 키 설정 후 확인할 것

1. 루트 `.env`에 해당 출처의 발급된 키와 승인 정보를 설정한다. 값은 채팅·커밋에 넣지 않는다.
2. 저장소 루트에서 `python collector/probe.py --source saramin --company 카카오` 또는 `--source wanted`로 조회한다.
3. 인증 성공, 매칭된 회사·제목·지역, 공고 상태·마감일과 원문 매핑을 확인한다.
4. 사람인은 실제 응답의 `modification-timestamp` 존재 및 `sort=ud` 정렬을 추가로 확인한다. 이 명령의 공고 예시만으로 정렬 전체를 확인했다고 판단하지 않는다.
5. 한도에 걸리면 일부 수집으로 판단하고 필요한 범위에서만 다시 조회한다. 기본 출처당 16회 요청·기업당 1페이지다.
6. 실제 조회가 성공한 뒤 DB import·추천·알림 연동을 별도로 확인한다.

설정 이름과 명령 옵션은 [수집기 안내](../collector/README.md)를 따른다.
