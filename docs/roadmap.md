# 단계별 진행

각 단계의 완료 기준을 실제 결과로 확인한 뒤 다음 단계로 진행한다.

| 순서 | 작업 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 1 · P1 | PostgreSQL 회귀 검증·CI·운영 기본기 | 새 DB와 V1~V7 기존 DB의 V8 마이그레이션·핵심 API 통과 | 완료 (2026-10-06 재검증) |
| 2 · P1 | 추천 품질 평가 세트 | 가상 공고 40개·여러 프로필의 기대 순위, 점수/순위 재현, 가중치 전후 개선·악화 설명 | 완료 (2026-10-02) |
| 3 · P2 | ai-service 의미 유사도 | 계약·입력/개인정보 범위·모델 버전·0~100 보정, 타임아웃/장애 시 0점, 평가 세트로 개선 확인 | 완료 (2026-10-02) |
| 4 · P2 | 파일 추출·OCR | 서버 크기/형식 검증, PDF 텍스트 → 이미지/스캔 OCR, 사용자 확인 후 분석, 취소/보관 정책 | 완료 (2026-10-06, Java 21 Linux 한국어 OCR 포함) |
| 5 · P3 | 실제 수집·배포 | 대상 사이트 이용 조건, 출처/수집 시각/중복/마감, 가상/실제 구분, 인증/백업/모니터링 | 출처 추적·운영 API 인증·컨테이너·백업/복원 기반 완료, 실제 출처/인증 UI/운영 환경 연결 필요 |

1단계 구현과 운영 정책은 [operations.md](operations.md)에 기록한다.
2단계에서는 현재 40개 가상 공고를 공통 입력으로 사용하고 백엔드 신입·경력, 프론트엔드,
데이터/AI, 클라우드/DevOps, 기술 부족 프로필의 기대 순위와 이유를 명시한다.
2단계 기준 평가의 의미 유사도는 0점이며 가중치는 필수 35%, 우대 20%, 의미 20%, 경험 15%, 희망조건 10%다.
기준 평가 결과를 먼저 고정하고 가중치 변경 및 AI 도입 결과를 같은 세트로 비교한다.

실제 수집 사이트, 운영 인프라와 공개 범위는 5단계 진입 시 정한다.
이용 조건이나 인증이 정해지지 않은 상태로 수집·공개하지 않는다.

## 1단계 검증 결과 · 2026-10-02

- `backend/gradlew.bat test postgresTest --console=plain`: 성공. 단위/H2/오류 계약 19개,
  실제 PostgreSQL 회귀 7개(새 DB + V1~V5 + prod 시드 비활성) 모두 통과, 건너뛰기 없음.
- `frontend/npm.cmd test`: 13개 통과. `npm.cmd run check`: 문법 검사 성공.
- 기존 V1~V5 SQL은 수정하지 않았으며 V6에 추천 보존 기간 조회/삭제용 인덱스만 추가했다.
- CI workflow는 저장소에 추가했다. 원격 push/PR 및 GitHub Actions 실행은 이 작업에서 수행하지 않았다.
- 백업·복원·로그/알림·비밀값 정책은 문서화했다. 운영 인프라 연결과 공개 배포는 5단계의 작업이다.
- 당시 다음 작업은 2단계 평가 세트였다. 완료 결과는 아래에 기록했다.

## 2단계 검증 결과 · 2026-10-02

- 가상 공고 40개와 가상 프로필 10개, 33개 기대 순서 쌍/이유, 20개 부분 점수·기술 목록 기대값을 작성했다.
- 400개 점수·근거·누락 설명과 열린 36개 공고의 순위를 고정했다. 반복 실행, 입력 순서 역전,
  별칭·지역 동등 표현의 결과 재현을 검증한다.
- `recommendationEvaluation` 작업으로 운영 기준·후보 가중치의 결과와 순위 변화 보고서를 생성한다.
  CI는 회귀 테스트 전에 보고서를 만들어 테스트 실패 시에도 비교 자료를 artifact로 남긴다.
- 기존 운영 가중치는 유지했다. 지역 가중치를 높인 실험은 서울 선호에서 개선됐지만
  필수 기술 충족 구분이 약해지고 DevOps 상위 후보가 줄어드는 악화가 있어 채택하지 않았다.
- 경력 기간/요구 연차와 업무 의미 반영의 현재 한계를 기대 미충족 사례로 기록했다.
- `gradlew.bat test postgresTest recommendationEvaluation --console=plain`: 성공.
  단위/H2/평가 24개와 PostgreSQL 7개 통과. 프론트 테스트 13개·문법 검사 통과.
- 상세 기준은 [추천 품질 문서](recommendation-quality.md), 실제 순위 변화는
  [evaluation-v1 비교 보고서](evaluation-v1-comparison.md)에 있다.
- 다음은 3단계 Spring Boot ↔ FastAPI 의미 유사도 계약·모델 버전·장애 대체·동일 평가 세트 검증이다.

## 3단계 검증 결과 · 2026-10-02

- 고정 다국어 임베딩 모델의 0~100점 보정 결과를 기존 의미 유사도 20% 가중치에 연결했다.
  HTTP 계약, 전달 텍스트·개인정보 범위, 모델 버전 스냅샷, 5초 제한과 장애 시 0점 대체를 명시했다.
- 운영 기본 개인정보 설정과 합성 프로젝트 설명 포함 설정을 모두 40개 가상 공고·10개 프로필로 비교했다.
  별칭 동등성 프로필을 제외한 엄격한 기대 쌍은 각 설정에서 1건 개선·0건 악화였다.
  기본 설정에서는 백엔드 경력 프로필의 기대 Top5 후보가 5개에서 4개로 줄었고,
  AI 문서 업무 및 지역 선호의 일부 기대는 여전히 미충족이다.
- Python 모델·API 테스트 3개, 백엔드 H2/평가 테스트 27개, 실제 PostgreSQL 회귀 7개,
  프론트 테스트 13개와 문법 검사, 라이브 모델의 두 설정 순위 게이트를 로컬에서 통과했다.
  CI 작업은 추가했으며 원격 실행은 push/PR 후 확인한다.
- 계약·운영 방법은 [의미 유사도 문서](semantic-integration.md), 상세 순위는
  [운영 기본 설정 보고서](semantic-v1-privacy-default.md)와 [합성 설명 포함 보고서](semantic-v1-evaluation.md)에 있다.
- 다음은 4단계 파일 업로드 검증, PDF 텍스트 추출, OCR, 사용자 수정·확인 흐름이다.

## 4단계 진행 결과 · 2026-10-02

- 서버에 10MiB·확장자/MIME/파일 서명 검증과 PDFBox 페이지별 텍스트 추출을 추가했다.
  이미지·텍스트 없는 PDF 페이지는 로컬 Tesseract 한국어/영어 OCR로 처리한다.
- 파일 모드에서는 추출 결과를 수정하고 `텍스트 확인`을 누른 뒤에만 기존 키워드 비교를 실행한다.
  파일 교체·삭제·취소와 오류 시 이전 결과로 임의 점수를 만들지 않는다.
- H2 테스트의 PDF/스캔 경로·형식/크기 오류, 실제 PostgreSQL 회귀 7개, 프론트 테스트 14개,
  Chrome 데스크톱/모바일 브라우저 흐름이 통과했다. 별도 컨테이너에서 `kor+eng` OCR 명령행을 실행해
  브라우저 스크린샷의 한국어·영어 텍스트 추출을 확인했다.
- 이 Windows 호스트에는 Tesseract가 없어 Java의 실제 OCR 엔진 테스트 1개는 건너뛰었다.
  CI Linux 작업은 엔진·한국어 데이터를 설치한 뒤 실제 OCR 테스트를 실행하도록 구성했으며 원격 실행은 아직 확인 전이다.
- API·크기/쪽수 제한·오류·취소·임시 파일 정책은 [파일 추출 문서](file-extraction.md)에 있다.

## 2026-10-06 완료 기준 재검증과 운영 기반 보완

- Java 21 Linux 컨테이너의 H2/API/추천/인증/파일 추출 테스트 **36개 통과, 건너뛰기 없음**.
  실제 Tesseract `kor+eng`로 영문·한국어 공고 이미지를 읽는 테스트를 포함한다.
  CI에서는 OCR 엔진이 없으면 실패하도록 설정했다.
- 실제 PostgreSQL 테스트 **10개 통과**. 새 DB와 V1~V7 기존 DB를 V8까지 순차 업그레이드하고
  프로필·목록 페이지네이션·추천 재사용·시드 중복·보존 기간을 검증했다.
  각 업그레이드 뒤 실제 공고 출처 추적·재관측 중복 방지·마감 갱신·원문 이력을 확인한다.
  별도 PostgreSQL DB에서 백업 스크립트와 격리 복원·정리도 통과했다.
- 기존 40개 공고·10개 프로필의 규칙 평가 보고서를 다시 생성했다.
  고정 모델 테스트 **3개 통과**, 실제 Spring HTTP 클라이언트로 두 개인정보 설정의 AI 평가를 실행했다.
  두 설정 모두 독립 선호 순서 **1건 개선·0건 악화**이며 기존 보고서에 기록된 Top5 한계는 유지된다.
- 프론트 테스트 **14개**와 Vite 빌드가 통과했다. CI에 `npm ci`와 lockfile 캐시를 추가해
  React 프론트 변경 후에도 의존성을 설치하고 테스트·빌드하도록 수정했다.
- V8에 `SYNTHETIC/REAL/LEGACY`, 출처·외부 ID·수집/갱신 시각·내용 해시·JSON 원문 변경 이력을 추가했다.
  가상/실제 구분과 실제 공고 원문 링크·수집 시각은 프론트에도 표시한다.
- 운영 API는 서명된 OIDC 토큰의 issuer/audience/만료를 검사한다. 두 계정의 프로필·추천이
  서로 노출되지 않는지 실제 서명 토큰과 JWKS로 확인했다. 데모 계정은 운영 계정으로 사용하지 않는다.
- 배포용 Dockerfile, 비밀 파일을 사용하는 로컬 리허설 Compose, 백업·격리 복원·상태 점검 도구를 추가했다.
  Linux에서 Gradle wrapper를 실행할 수 있도록 줄바꿈 규칙도 보완했다.
- 두 런타임 이미지 빌드와 별도 Compose 프로젝트의 운영 프로필 기동도 통과했다.
  secret 파일 주입, readiness, 빈 공고 목록, 비인증 프로필 401·requestId,
  백업 생성·격리 복원, 모니터링 정상 판정을 확인하고 검증용 컨테이너를 정리했다.

P3의 실제 수집·공개 배포는 아직 완료되지 않았다. 대상 사이트/API와 허용 근거,
배포 계정·도메인, 인증 제공자 및 프론트 로그인, 암호화 외부 백업과 알림 채널을 연결해야 한다.
상세 계약은 [job-ingestion.md](job-ingestion.md), 실행·연결 절차는 [deployment.md](deployment.md)에 기록했다.
