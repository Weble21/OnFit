# 실제 공고 등록과 출처 추적

## 자소설닷컴 취업달력 검토 (2026-10-12)

대상 후보: [자소설닷컴 취업달력](https://jasoseol.com/recruit). [현행 서비스 이용약관](https://jasoseol.com/terms)은 허가 없는 수집로봇·스파이더·스크래퍼 등 자동화 수단을 통한 사용자 콘텐츠·정보 수집 또는 접근을 금지한다. AI Agent가 브라우저를 조작하는 방식도 자동화된 접근이므로, 서면 허가나 공식 제휴 계약이 확인되기 전에는 이 사이트용 크롤러를 만들거나 활성화하지 않는다. 공개 페이지를 볼 수 있다는 사실이나 `robots.txt`의 설정만으로 수집·저장·재게시 허가를 추정하지 않는다. 현재 저장소에는 자소설닷컴 허가 증빙이 없다.

허가를 받는 경우 수집 가능 페이지, API/브라우저 접근 방식, 호출 주기와 트래픽, 본문 저장·AI 처리·재게시, 원문 링크·출처 표시, 보관·삭제와 마감 상태 제공 범위를 계약서에 명시하고 출처 정책에 증빙을 기록한다. 이후 사이트별 수집기는 허용된 경로에서만 원문을 가져온다. 허가 전에는 사용자가 직접 제공한 공고 텍스트나 별도 이용 허가가 확인된 기업 공식 공고·공공 API 데이터로 AI 추출기를 개발·평가할 수 있다.

AI 추출기는 수집기와 분리한다. 입력은 확인된 공고 본문과 출처 ID·URL·수집 시각이며, 출력은 `requiredSkills`, `preferredSkills`, `careerLevel`, `location`과 각 값의 원문 근거 위치, 모델 버전, 추출 상태다. 원문에 없는 값은 `null` 또는 빈 목록으로 남기고, 필수·우대 기술을 구분하지 못하면 임의로 필수로 승격하지 않는다. 기존 `SkillNormalizer`로 별칭을 정규화하고, 근거 문구가 실제 입력에 존재하는지 검증한 뒤 운영자 검토를 거쳐 `JobImportService`에 전달한다. 외부 AI 제공자에 본문을 보내려면 그 범위가 출처의 허가와 개인정보 처리 정책에 포함되는지 별도로 확인한다. 현재 `ai-service/`의 임베딩 모델은 추천 점수용이며 구조화 필드 추출 모델은 아니다.

## 고용24 공식 API 연결 (2026-10-12 확인)

첫 수집 출처는 고용24 채용정보 목록·상세 Open API다. [공식 목록 명세](https://www.work24.go.kr/cm/e/a/0110/selectOpenApiSvcInfo.do?fullApiSvcId=000000000000000000000000000000)와 [공식 상세 명세](https://m.work24.go.kr/cm/e/a/0110/selectOpenApiSvcInfo.do?fullApiSvcId=000000000000000000000000000000%5E000000000000000000000000000001%5E000000000000000000000000000003)를 기준으로 한다. 웹 페이지 스크래핑은 사용하지 않는다. [고용24 Open API 이용안내](https://www.work24.go.kr/cm/e/a/0110/selectOpenApiIntro.do)는 회원 신청, 담당자 심사, 인증키 발급을 요구한다. 따라서 승인받은 키와 승인 범위를 확인하기 전에는 수집을 켤 수 없다. 키를 저장소·로그·문서에 적지 않는다. 제공처가 요구하는 원문 이동 링크와 출처 문구·이미지는 공고 상세 화면에 표시한다. 사용 목적·재배포 범위가 승인 내역에 포함되는지 운영자가 확인하고, 조건이 바뀌면 수집을 중지해 재검토한다.

승인 후 운영 환경에 다음 값을 설정한다. `ONFIT_WORK24_PERMISSION_EVIDENCE`에는 승인 번호·승인받은 사용 범위 등 감사 가능한 설명을 넣으며 키 자체를 넣지 않는다. `ONFIT_INGESTION_ALERT_URL`은 JSON POST를 받는 HTTPS 운영 알림 엔드포인트다. 운영에서는 비밀 저장소에서 값을 주입한다.

```dotenv
ONFIT_INGESTION_ENABLED=true
ONFIT_WORK24_ENABLED=true
ONFIT_WORK24_AUTH_KEY=<발급된-키>
ONFIT_WORK24_PERMISSION_EVIDENCE=<승인-번호와-허용된-용도>
ONFIT_INGESTION_ALERT_URL=https://<운영-알림-엔드포인트>
```

수집기는 UTC 02:00·14:00(한국 시간 11:00·23:00)에 `개발자` 키워드의 최근 3일 목록을 조회한다. 한 페이지 30건, 기본 최대 2페이지로 제한하며 `ONFIT_WORK24_MAX_PAGES`는 1~10만 허용한다. 목록의 구인인증번호마다 공식 상세 API를 호출한다. 같은 `sourceName + externalId`는 기존 import 서비스의 고유 키·해시·수집 시각 규칙으로 중복 등록을 막고 변경 이력을 남긴다. 원문에 구조화된 기술 스택이 없으므로 필수·우대 기술은 빈 목록으로 저장하며 추측하지 않는다. 일시적인 목록 누락이나 최근 3일 창에서 사라졌다는 이유만으로 공고를 마감하지 않는다. 확인된 마감일이 지난 공고만 매일 UTC 00:30에 `EXPIRED`로 바꾸고 변경 이력을 남긴다. `채용시까지`처럼 날짜를 알 수 없는 공고의 종료는 원천의 명시적 종료 신호를 확인할 수 있을 때 추가해야 한다. 현재 그런 공고는 원문에서 최신 상태를 확인하도록 안내한다.

`GET /api/admin/jobs/collection/status`는 최근 성공·실패 시각, 연속 실패 횟수와 페이지 상한으로 일부 결과만 읽었는지(`partialCoverage`)를 `jobs:import` 권한자에게 제공한다. 첫 실패·복구·부분 수집·전체 범위 회복 시 설정된 알림 URL에 `source`, `state`, `at`, `detail` JSON을 전송한다. 만료 작업 실패도 알린다. 인증키·요청 URL·응답 본문은 로그와 알림에 넣지 않는다. 운영 모니터는 최근 성공이 24시간 이상 없거나 연속 실패가 1 이상이거나 `partialCoverage=true`인 상태를 경고하고, 알림 URL 자체의 전달 실패 로그도 감시한다. 수집은 단일 백엔드 인스턴스에서만 켠다. 다중 인스턴스에서는 분산 잠금 또는 별도 작업 실행기로 이전해야 한다.


고용24 API는 연결 코드를 마련했지만, 이 저장소에는 발급된 인증키나 개별 사용 승인이 없다.
실제 외부 수집은 승인 정보를 설정하고 명시적으로 활성화한 운영 환경에서만 실행된다.

## 출처 승인

사이트를 정한 뒤 이용약관/API 약관에서 자동 접근, 본문 저장, 재게시, 갱신 빈도,
원문 링크·출처 표시, 보관·삭제 범위를 확인한다. robots.txt만으로 수집 허가를 판단하지 않는다.
허용 근거·확인 날짜·약관 URL을 기록하고 명시된 빈도로 수집한다. 약관이 변경되면 재검토한다.
수집기는 원문의 외부 ID, HTTPS URL, UTC 관측 시각을 전달한다.

아래 설정은 테스트용 도메인을 사용한 형식 예시이며 실제 수집 허가가 아니다.
허용 근거가 확인된 사이트만 배포 환경의 별도 설정에 넣는다.

```yaml
onfit:
  ingestion:
    enabled: true
    sources:
      approved-source:
        allowed-host: jobs.example.test
        terms-url: https://jobs.example.test/terms
        reviewed-on: 2026-10-06
        permission-evidence: '승인 문서/공식 API 계약의 식별자와 허용한 범위'
```

허용 호스트와 정확히 일치하는 HTTPS URL만 받는다. 사용자 정보가 들어간 URL,
다른 호스트, HTTP, 443 이외 포트는 거부한다. 이 API가 원문 URL을 직접 요청하지는 않는다.
운영에서는 `jobs:import` scope가 있는 접근 토큰만 등록·이력 조회를 할 수 있다.

## 등록 계약

`POST /api/admin/jobs/import`, `Content-Type: application/json`

```json
{
  "sourceName": "approved-source",
  "externalId": "posting-123",
  "sourceUrl": "https://jobs.example.test/jobs/123",
  "observedAt": "2026-10-06T00:00:00Z",
  "content": {
    "companyName": "회사명",
    "title": "백엔드 개발자 채용",
    "roleName": "백엔드 개발자",
    "industry": "IT",
    "companySize": null,
    "careerLevel": "경력 무관",
    "description": "원문에서 확인한 설명",
    "responsibilities": "API 개발",
    "location": "서울",
    "deadline": null,
    "status": "OPEN",
    "requiredSkills": ["Java"],
    "preferredSkills": ["PostgreSQL"]
  }
}
```

- 최초 등록은 201, 재관측·갱신은 200이다. 응답은 `{job, created, changed}`다.
- `sourceName + externalId`가 DB 유일 키다. 같은 원문의 재시도는 공고나 변경 이력을 늘리지 않는다.
  동시에 신규 등록한 경우 한 요청이 409를 받을 수 있으므로 수집기는 최신 시각으로 다시 시도한다.
- 최초 수집 시각은 보존하고 마지막 관측 시각만 갱신한다. 이전 관측보다 오래된 요청은 409다.
  동일 시각에 다른 원문을 전달해도 409다. 5분을 초과한 미래 시각은 400이다.
- 원문 URL, 내용, 마감일, 상태가 바뀌면 SHA-256과 JSON 원문 스냅샷을 저장한다.
  당시 약관 URL·허용 근거·검토 날짜도 변경 이력에 남긴다. 과거 스냅샷은 덮어쓰지 않는다.
- 마감일 없는 상시 채용도 `OPEN` 목록과 추천에 들어간다. 이미 마감일이 지난 `OPEN` 등록은
  `EXPIRED`로 저장한다. 목록·추천은 서비스 날짜가 지난 공고를 즉시 제외하므로 재수집이 늦어도 노출되지 않는다.
  수집기가 폐쇄·삭제를 확인한 경우 `CLOSED`로 갱신한다. 일시적인 수집 실패는 마감으로 추정하지 않는다.
- 출처별 외부 ID가 서로 다르면 별도 공고로 보존한다. 사이트 간 동일 공고 통합은 별도 규칙과 검토가 필요하다.
- `GET /api/admin/jobs/{jobId}/revisions`는 관리자에게 수집 원문·상태 변경 이력을 반환한다.

공개 목록·상세·추천 안의 공고는 `origin`, `sourceName`, `sourceUrl`, `collectedAt`, `lastSeenAt`을 반환한다.
`SYNTHETIC`은 가상 시드, `REAL`은 승인된 출처에서 등록한 공고, `LEGACY`는 출처를 확인하지 못한 기존 공고다.
V8은 기존 시드 키가 있는 행만 가상으로 표시하므로 출처 불명 데이터를 실제로 간주하지 않는다.
프론트는 이 구분과 실제 공고의 원문 링크·수집 시각을 표시한다.

## 보관과 운영 연결

현재 원문 이력은 공고가 존재하는 동안 보존하며 공고 삭제 시 함께 삭제된다.
실제 출처가 정해지면 해당 사이트의 보관·삭제 조건에 맞춰 별도 만료 작업을 추가해야 한다.
실제 출처 승인, 수집기 연결, API 키 주입, 갱신 스케줄·장애 알림을 마친 뒤 활성화한다.
가상 테스트 도메인이나 가상 회사 데이터를 실제 운영 공고로 등록하지 않는다.
